# RMb30 · Malody Link 1.5.2

节奏大师自制谱的 B30 成绩辅助 App，采用 O20 + N10 分表。

只收录当前服务器有效谱面的本地成绩，通过内置本机读取同步，并支持按 QQ 号上传、合并和恢复云端存档。当前适配实测 Malody V 6.6.42 的 `.mrv` 格式。

## 下载

正式安装包通过 [GitHub Releases](https://github.com/gmiya233/RMb30/releases/latest) 提供，文件扩展名统一为 `.APK`。

## 页面导航

底部固定「首页 / B30 / 排行榜 / 歌曲 / 设置」五个入口，内容滚动时导航保持可用。

- 首页：rating 试算、成绩记录数、O20/N10 收录数量、同步本机成绩、实际 B30 缩略图及最近50次游玩；按时间倒序展示，保留同曲重复游玩。
- B30：完整分表、键数标识、缩放、保存相册及绿色成绩上传按钮；保留 rating 倍率和单曲预览参数。
- 排行榜：总榜、歌曲热度／好评榜、谱师热度／好评榜采用横向卡片，右侧「查看更多」打开前50名；单曲榜独立选歌查看。
- 歌曲：支持综合、曲名、歌手、谱师、等级、键数搜索，可隐藏未提供等级的歌曲；卡片每行1～5列，默认3列。详情展示各谱面下载量、键数和复制歌名图标，并可评论、打1～5星及查看单曲榜。
- 设置：两列紧凑卡片，首次配对入口置顶；包括 QQ 云存档、玩家名片、谱库与 JSON 导出。「关于 Malody Link → 获取更新」从服务器检查、下载和校验安装包，再交给 Android 确认安装。

整体采用浅色主题，五个主页面使用指定角色的半透明背景。
页面适配系统安全区与大字号；横屏高度不足时收起 B30 标题及次要说明，保留图片和操作入口。返回键先回首页。界面操作不改写原始成绩。

## rating 与 SC 难度

单曲数值正式命名为 rating。SC1～4→12级，SC5～13→13级，SC14及以上→15级；优先于谱库数字等级，其他谱面保持原 MaV→RM 表。O20、N10 标题右侧分别显示单曲 rating 总和除以20／10的分表 rating，缺位按0计。综合 rating 仍为两表单曲总和除以30。键数是独立描述信息，不改变 rating 计算或榜单版本。

## 云端排行榜与歌曲信息

服务器运行 Java 排行汇总程序，使用与 Android 相同的谱库校验、O20/N10 分类和 rating 规则，只读取现有原始成绩，发布派生的 v2 榜单。部署前校验既有玩家结果并保存备份，升级不清除玩家存档或原有排行；v2 不可用时客户端回退到既有 v1 索引。服务构建、部署、缓存和恢复方式见 [server/README.md](server/README.md)。

客户端上传仍维护兼容 v1 的内容哈希索引；索引发布失败保留已同步成绩，并提示下次重试。本地试算参数不上传。总榜按歌曲 SID 去重，每首取最高 rating，缺位按0计；同一歌曲任意当前谱面位于 promote 时归入 N。未知判定不参与排行。

歌曲热度按 `stats.download_count` 汇总同歌各谱面；谱师热度按署名汇总作品下载量。歌曲／谱师好评榜按平均星级、评价数、下载量排序；同一 QQ 对同歌保留最新评价，并保留原始评价文件。每位玩家对同歌同一谱师只计一次评分，不因多个难度重复计票。谱师热度默认隐藏配置名单，开关可显示其中其他谱师，imddesigner 始终隐藏；谱师好评榜不受该开关影响。

结果缓存供离线查看，手动刷新立即读取；榜单按服务器和谱库版本隔离，同分采用并列名次。QQ 仅为存档编号，尚未验证归属。
歌曲元数据来自只读 malody.db 的 songs/charts 表。升级时只为同 CID、同 server_hash 的旧缓存补齐描述字段，不恢复已删除谱面。云端曲绘缩略图独立存放在 `/RMB30/_song_art/`，不占用玩家目录，不扩展 Data1 的读取范围；缺失曲绘使用占位图。App 仅使用专用 Rank1 读取发布的缩略图，不包含 GMIYA 测试账号。运行 `python tools/prepare_song_catalog.py` 更新构建用目录，增加 `--publish-art` 可按提示临时输入源账号密码，发布384像素缩略图；源账号凭据不写入文件或安装包。

## 本地玩家名片与称号

设置页可选择本地头像和昵称，B30 页的奖章图标可选择称号；头像、昵称和称号偏好不上传。默认称号为「小师妹」，真实记录 rating 达到10／11／12／13，分别解锁「萌新／高手／大师／龙币」。未手动选择时自动显示当前 rating 对应称号；已解锁的低级称号仍可选择。

原始准度严格大于99.8%的当前谱库歌曲可解锁歌名称号；等于99.8%不解锁。预览调整与示例成绩不参与任何称号解锁。失去条件的所选称号回退到当前自动称号。

## 筛选规则

1. 默认使用 Data1 只读账号，通过 WebDAV GET `/dav/malody.db` 更新目录，仅保留歌曲与谱面 `exist=1` 的条目。
2. 匹配本机 `.mc` 文件名、游戏模式和歌曲身份。服务器路径含 `_song_原始歌曲ID` 且本机有歌曲ID时必须一致；缺少可用ID时要求曲名一致。不能唯一匹配的谱面跳过。
3. 按用户要求，不下载服务器谱面，不比较音符或节奏内容；目录匹配标记为 `catalog_identity`，不声称内容相同。
4. 把已匹配的本地谱面 MD5 关联到服务器 CID 和目录版本哈希，再用回放内的本地 MD5 确定其对应谱面。
5. 仅保存有效谱库映射的成绩，跳过未知或重复回放。目录更新后失效的谱面成绩不再展示或导出。

这里是目录归属匹配，不是防作弊验证。玩家身份来自本地回放，未做账号所有权验证。分数和准确率字段仍标为待核对，不作为已验证的比赛成绩。

## 手机独立使用（内置读取）

Android 11及以上，只需要安装 Malody 和本项目 APK，不需要额外安装 Shizuku 或连接电脑。

1. 默认谱库账号已经配置，无需玩家填写。同步时自动更新目录（每6小时检查一次），设置页「更新谱库（默认账号）」可手动立即刷新。网络失败时保留缓存目录并明确提示。
2. 打开「同步本机成绩」，或设置页置顶的「首次配对」。页面根据当前状态显示需要完成的一步，已配对时直接显示同步入口。
3. 未开启开发者模式时，按提示前往版本信息解锁，完成后返回App。已解锁不会重复要求连点版本号。
4. 开启无线调试后，**直接点「无线调试」文字或整行空白区域进入详情**；右侧开关只负责开启，不是进入按钮。App中有两张脱敏重绘操作图，分别说明进入详情和找到「使用配对码配对设备」。vivo/iQOO平板使用开发者选项入口，避免手机专用详情跳转静默返回。
5. 可先点「开启六位码自动识别」，阅读说明后，在系统辅助功能中手动开启「Malody Link 配对码自动识别」，返回App。已有配对的玩家从「遇到问题 / 连接选项 → 六位码自动识别设置」进入。该辅助功能不会被App自行授权。
6. 点击「开始配对并自动导入」，允许通知，在系统详情中点「使用配对码配对设备」。启用自动识别时，保持窗口打开，App尝试读取窗口文本并直接提交到本机；只在本次配对后的3分钟内生效。未启用或系统保护了窗口文本时，仍可下拉通知手动输入。成功后自动导入。系统六位码弹窗仍需要玩家在系统页面点击。
7. 日常同步在前台服务中执行，离开页面也可继续。短暂传输中断会有限重连，已有成绩保留；使用文件大小与修改/变更时间检查回放，未变化且谱库映射未变化时跳过正文读取。谱库或映射变化会重新检查。
8. 手动端口、分屏配对、重新配对和系统设置入口收在「遇到问题 / 连接选项」内。

内置的是 LibADB 本机连接客户端与配对组件，不是把 Shizuku APK 嵌套安装；系统配对无法省略。连接固定使用127.0.0.1，不接收远端主机地址。配对码不保存，本机客户端私钥与证书只存本 App 私有目录，禁止系统备份。

自动识别只接受精确系统设置包的配对窗口、明确的配对码标签或资源ID和唯一六位数字，不扫描其他App，不截图，不点击系统授权控件，也不将配对码写入日志、文件或上传。开始、成功、超时和停用均限制识别生命周期。辅助功能配置明确 `isAccessibilityTool=false`，不冒充残障辅助工具来读取被系统保护的内容；厂商或系统不开放文本时使用手动输入。

读取仅限 Malody `chart/*.mc`、谱面目录的jpg/jpeg/png/webp曲绘和 `replay/*.mrv`；路径、远端规范路径、输出大小与读取超时均受限，不提供任意终端入口，也不修改 Malody 文件。正式设置页不再显示 Shizuku、USB 调试导入和回放文件入口；相关兼容实现保留在源码中，供开发测试使用。

第三方组件许可随APK放在 assets/licenses/，依赖固定版本和SHA256见构建脚本与「内置读取.md」。

## QQ 云存档

在「设置」页点「设置 QQ 并同步」，填写自己的 QQ 号，保存后自动创建服务器 `/RMB30/<QQ>/` 存档并合并成绩。首次设置会迁移原有本机成绩；以后切换 QQ 使用各自独立的本地成绩文件，原存档保留。

默认开启「本机读取后自动合并到云端」。也可以手动「合并同步云端（上传＋拉取）」；更换手机后，设置同一个 QQ 即可恢复，或使用「只从云端拉取」。云端拉取本身不需要无线调试，读取 Malody 文件仍需完成原有系统授权。

重复记录按 ID 去重，多次游玩分别保留，由成绩图选出每首最佳成绩。同 ID 数据不同时保留本机版本，云端原件仍保留；网络失败不影响已经保存的本机成绩。只上传当前服务器目录匹配的成绩，不上传试算参数、回放文件或设备密钥。

QQ 目前仅作存档编号，不验证 QQ 归属；共享服务器账号也不提供每位玩家的独立权限。QQ 机器人尚未接入。协议和构建配置见 [云端存档.md](云端存档.md)。

## USB 测试

确保手机 USB 调试已授权，安装 APK 后在项目根目录运行：

```powershell
python tools/prepare_usb_sync.py
```

脚本会提示输入服务器密码，拉取谱库和本机谱面做内容核验，只将匹配回放交给已安装的测试 App。`--serial` 可指定设备序列号。USB 入口仅用于当前可调试测试版，发行版需要单独设计受控导入接口。

## 构建

需 Windows 与 Java 17+（本机实测 Java 25），SDK、依赖、签名与构建产物均在 E 盘项目内。SDK 从 Google 官方仓库获取，Shizuku API 13.1.5 从 Maven Central 获取，校验下载摘要。

```powershell
python tools/prepare_usb_sync.py --prepare-only
python tools/build_android.py
```

APK 输出到 `dist/Malody-Link-1.5.2.APK`。内置服务器谱面目录快照和示例曲绘，不包含测试玩家成绩、GMIYA账号密码或登录令牌。按用户授权打包的 Data1 只读配置和 Rank1 成绩目录配置分别来自被 Git 忽略的 `.secrets/default-reader.json`、`.secrets/default-rank.json`，构建时复制到被忽略的对应 assets 文件。默认账号可从 APK 提取；Data1 应仅能读取数据库，Rank1 应限定在 RMB30 目录。不要将这些私有配置提交到 Git。

## O20 + N10 成绩图

点击底部「B30」或首页的成绩图。按服务器歌曲的 promote 标记分表：普通歌曲 O20，新歌 N10。同一首歌（sid）取最佳成绩，每组分别按自定义rating排序；缺位显示「待收录」，综合 rating 为两表 rating 合计除以30，缺位按0计。

- 成绩卡片包括曲绘、曲名、等级、成绩、A～E判定、准度与rating。原始等级>16时按用户提供的 MaV→RM 对照表转换（例如23→11、29→13、32→14），16级按8级处理，卡片显示与换算均使用该折算等级，原始数据保留。
- 节奏大师字标只位于分表右上角。App 启动图标没有更改。该字标以 Canvas 字体绘制，不声明为腾讯官方 Logo 原图。
- 「示例布局」展示30首实际谱库歌曲配虚构示例成绩，图中有显著示例标记；实际记录模式不补造分数。
- 可调整单曲预览等级、准度、判定，或全图判定和倍率。预览参数独立保存，卡片加 * 标记，不修改原始成绩。改变判定不自动重新判定一次历史游玩的准度。
- 预览默认完整适应可用区域，支持双指缩放、放大后拖动、双击或按钮复位。点击「保存到相册」直接存入 Pictures/Malody Link，输出1500×1664 PNG。Android 10及以上无需相册读取权限；Android 8～9需系统存储授权。
- 缺少曲绘时显示音符占位。USB 同步会复制已匹配成绩的曲绘，Shizuku 读取会尝试缓存对应谱面目录下的曲绘。

公式与锚点见 `换算规则.md`。这套换算是用户自定义规则，不是 Malody 官方 MM；原始分数、准度及判定字段仍按待核对状态显示。

## 当前边界

- 已实现本地读取、服务器目录匹配、白名单筛选、去重、离线保存、JSON 导出和 QQ 云存档合并／恢复。
- QQ 机器人尚未接入；云存档包含服务器 CID、谱面哈希、原始数值字段和字段验证标记，便于后续对接。

- 内置读取的系统首次配对与厂商系统差异需要真机确认；组件自检不等同于完整端到端配对通过。兼容读取代码保留，但正式设置页只保留常用本机同步入口。


## 1.5.2 安装包

正式版本号为1.5.2（versionCode 18）。关闭应用调试，构建时排除真机测试组件及其注册入口，沿用既有签名身份，支持覆盖相同签名的旧版本。

开发测试包需显式运行 `python tools/build_android.py --test-apk`，测试结束后应覆盖安装正式包。键数 metadata 可运行 `python tools/prepare_chart_keys.py` 准备，`MALODY_RANK_CONFIG` 指向项目外的专用构建配置。常规验证为 `python tools/test_ranking_features.py`、`python tests/test_community.py` 和 `python tests/test_chart_keys.py`。

应用内更新只在玩家点击「获取更新」时请求版本信息，安装包由玩家手动下载。客户端检查包大小、SHA-256、应用包名、版本号和现有签名，再通过只读文件提供器交给系统安装；首次安装来源授权和最终确认由 Android 处理。未实现歌曲音频下载／试听，也未接入小师妹宠物。

待核对的成绩字段和试算标记保留，版本号变化不代表字段验证状态改变。
