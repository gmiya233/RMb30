# RMb30 · Malody Link 1.2.0

节奏大师自制谱的 B30 成绩辅助 App，采用 O20 + N10 分表。

只收录当前服务器有效谱面的本地成绩，支持内置本机读取、可选 Shizuku 兼容读取、USB 同步和手动导入回放。支持按 QQ 号上传、合并和恢复云端存档。当前适配实测 Malody V 6.6.42 的 `.mrv` 格式。

## 页面导航

底部固定「首页 / B30 / 设置」三个入口，内容滚动时导航保持可用。

- 首页：综合换算试算、成绩记录数、O20/N10 收录数量、同步本机成绩、实际 B30 缩略图和最近十条有效成绩。最近成绩按游玩时间倒序排列。
- B30：直接查看完整分表、缩放和保存到相册。「调整与示例」菜单包含换算倍率、单曲参数、全图判定和示例布局。
- 设置：QQ 云存档、首次配对、兼容读取、谱库、手动导入、JSON 导出和版本。

页面适配系统安全区与大字号；横屏高度不足时收起 B30 标题及次要说明，保留图片和操作入口。返回键先回首页。界面操作不改写原始成绩。

## 筛选规则

1. 默认使用 Data1 只读账号，通过 WebDAV GET `/dav/malody.db` 更新目录，仅保留歌曲与谱面 `exist=1` 的条目。
2. 匹配本机 `.mc` 文件名、游戏模式和歌曲身份。服务器路径含 `_song_原始歌曲ID` 且本机有歌曲ID时必须一致；缺少可用ID时要求曲名一致。不能唯一匹配的谱面跳过。
3. 按用户要求，不下载服务器谱面，不比较音符或节奏内容；目录匹配标记为 `catalog_identity`，不声称内容相同。
4. 把已匹配的本地谱面 MD5 关联到服务器 CID 和目录版本哈希，再用回放内的本地 MD5 确定其对应谱面。
5. 仅保存有效谱库映射的成绩，跳过未知或重复回放。目录更新后失效的谱面成绩不再展示或导出。

这里是目录归属匹配，不是防作弊验证。玩家身份来自本地回放，未做账号所有权验证。分数和准确率字段仍标为待核对，不作为已验证的比赛成绩。

## 手机独立使用（内置读取）

Android 11及以上，只需要安装 Malody 和本项目 APK，不需要额外安装 Shizuku 或连接电脑。

1. 默认谱库账号已经配置，无需玩家填写。同步时自动更新目录（每6小时检查一次），首页「更新谱库（默认账号）」可手动立即刷新。网络失败时保留缓存目录并明确提示。
2. 打开「同步本机成绩」或「连接设置 / 首次配对」。页面根据当前状态显示需要完成的一步，已配对时直接显示同步入口。
3. 未开启开发者模式时，按提示前往版本信息解锁，完成后返回App。已解锁不会重复要求连点版本号。
4. 开启无线调试后，**直接点「无线调试」文字或整行空白区域进入详情**；右侧开关只负责开启，不是进入按钮。App中有两张脱敏重绘操作图，分别说明进入详情和找到「使用配对码配对设备」。vivo/iQOO平板使用开发者选项入口，避免手机专用详情跳转静默返回。
5. 点击「开始配对并自动导入」，允许通知，在系统详情中点「使用配对码配对设备」。保持弹窗打开，下拉通知输入六位码。成功后自动导入。系统六位码弹窗仍需要玩家在系统页面点击，不宣称可由普通App直接弹出。
6. 日常同步在前台服务中执行，离开页面也可继续。短暂传输中断会有限重连，已有成绩保留；使用文件大小与修改/变更时间检查回放，未变化且谱库映射未变化时跳过正文读取。谱库或映射变化会重新检查。
7. 手动端口、分屏配对、重新配对和系统设置入口收在「遇到问题 / 连接选项」内。

内置的是 LibADB 本机连接客户端与配对组件，不是把 Shizuku APK 嵌套安装；系统配对无法省略。连接固定使用127.0.0.1，不接收远端主机地址。配对码不保存，本机客户端私钥与证书只存本 App 私有目录，禁止系统备份。

读取仅限 Malody `chart/*.mc`、谱面目录的jpg/jpeg/png/webp曲绘和 `replay/*.mrv`；路径、远端规范路径、输出大小与读取超时均受限，不提供任意终端入口，也不修改 Malody 文件。Android 8～10可继续使用「Shizuku 兼容读取（可选）」或USB同步。

第三方组件许可随APK放在 assets/licenses/，依赖固定版本和SHA256见构建脚本与「内置读取.md」。

## QQ 云存档

首页点「设置 QQ 并同步」，填写自己的 QQ 号，保存后自动创建服务器 `/RMB30/<QQ>/` 存档并合并成绩。首次设置会迁移原有本机成绩；以后切换 QQ 使用各自独立的本地成绩文件，原存档保留。

默认开启「本机读取后自动合并到云端」。也可以手动「合并同步云端（上传＋拉取）」；更换手机后，设置同一个 QQ 即可恢复，或使用「只从云端拉取」。云端拉取本身不需要无线调试，读取 Malody 文件仍需完成原有系统授权。

重复记录按 ID 去重，多次游玩分别保留，由成绩图选出每首最佳成绩。同 ID 数据不同时保留本机版本，云端原件仍保留；网络失败不影响已经保存的本机成绩。只上传当前服务器目录匹配的成绩，不上传试算参数、回放文件或设备密钥。

QQ 目前仅作存档编号，不验证 QQ 归属；共享服务器账号也不提供每位玩家的独立权限。QQ 机器人尚未接入。协议和构建配置见 [云端存档.md](云端存档.md)。

## USB 测试

确保手机 USB 调试已授权，安装 APK 后在项目根目录运行：

```powershell
python tools/prepare_usb_sync.py
```

脚本会提示输入服务器密码，拉取谱库和本机谱面做内容核验，只将匹配回放交给已安装的测试 App。`--serial` 可指定设备序列号。USB 入口仅用于当前可调试测试版，发行版需要单独设计受控导入接口。

## 构建

需 Windows 与 Java 17+（本机实测 Java 25），SDK、依赖、签名与构建产物均在 E 盘项目内。SDK 从 Google 官方仓库获取，Shizuku API 13.1.5 从 Maven Central 获取，校验下载摘要。

```powershell
python tools/prepare_usb_sync.py --prepare-only
python tools/build_android.py
```

APK 输出到 `dist/Malody-Link-1.2.0.APK`。内置服务器谱面目录快照和示例曲绘，不包含测试玩家成绩、GMIYA账号密码或登录令牌。按用户授权打包的 Data1 只读配置和 Rank1 成绩目录配置分别来自被 Git 忽略的 `.secrets/default-reader.json`、`.secrets/default-rank.json`，构建时复制到被忽略的对应 assets 文件。默认账号可从 APK 提取；Data1 应仅能读取数据库，Rank1 应限定在 RMB30 目录。不要将这些私有配置提交到 Git。

## O20 + N10 成绩图

点击底部「B30」或首页的成绩图。按服务器歌曲的 promote 标记分表：普通歌曲 O20，新歌 N10。同一首歌（sid）取最佳成绩，每组分别按自定义换算分排序；缺位显示「待收录」，综合换算为两表换算分合计除以30，缺位按0计。

- 成绩卡片包括曲绘、曲名、等级、成绩、A～E判定、准度与换算分。原始等级>16时按用户提供的 MaV→RM 对照表转换（例如23→11、29→13、32→14），16级按8级处理，卡片显示与换算均使用该折算等级，原始数据保留。
- 节奏大师字标只位于分表右上角。App 启动图标没有更改。该字标以 Canvas 字体绘制，不声明为腾讯官方 Logo 原图。
- 「示例布局」展示30首实际谱库歌曲配虚构示例成绩，图中有显著示例标记；实际记录模式不补造分数。
- 可调整单曲预览等级、准度、判定，或全图判定和倍率。预览参数独立保存，卡片加 * 标记，不修改原始成绩。改变判定不自动重新判定一次历史游玩的准度。
- 预览默认完整适应可用区域，支持双指缩放、放大后拖动、双击或按钮复位。点击「保存到相册」直接存入 Pictures/Malody Link，输出1500×1664 PNG。Android 10及以上无需相册读取权限；Android 8～9需系统存储授权。
- 缺少曲绘时显示音符占位。USB 同步会复制已匹配成绩的曲绘，Shizuku 读取会尝试缓存对应谱面目录下的曲绘。

公式与锚点见 `换算规则.md`。这套换算是用户自定义规则，不是 Malody 官方 MM；原始分数、准度及判定字段仍按待核对状态显示。

## 当前边界

- 已实现本地读取、服务器目录匹配、白名单筛选、去重、离线保存、JSON 导出和 QQ 云存档合并／恢复。
- QQ 机器人尚未接入；云存档包含服务器 CID、谱面哈希、原始数值字段和字段验证标记，便于后续对接。
- 当前服务器使用 HTTP，登录沿用该服务现有协议；正式分发前应配置 HTTPS。
- 内置读取的系统首次配对与厂商系统差异需要真机确认；组件自检不等同于完整端到端配对通过。Shizuku 是可选兼容入口。


## 1.2.0 安装包

正式版本号为1.2.0（versionCode 13）。关闭应用调试，构建时排除所有真机测试组件及其注册入口。沿用已有签名身份，支持覆盖此前相同签名版本。正式包隐藏依赖 run-as 的 USB 调试导入按钮；日常使用内置本机读取或 Shizuku 兼容读取。开发测试包需显式运行 `python tools/build_android.py --test-apk`，测试结束后应覆盖安装正式包。

待核对的成绩字段和试算标记保留，版本号变化不代表字段验证状态改变。
