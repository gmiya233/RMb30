## Linux 部署

安装程序到 `/opt/malody-qqbot` 并创建独立 Python 虚拟环境，安装 `requirements.txt`。
配置文件 `/etc/malody-qqbot/config.json`：

```json
{"appid":"YOUR_APPID","rankings":"/var/lib/malody-qqbot/rankings","catalogue":"/var/lib/malody-qqbot/catalog-source/catalog.json","sandbox":false,"allowed_groups":[]}
```

`allowed_groups` 非空时只响应指定的群 openid；空数组表示响应平台服务范围内的群。
AppSecret 单独存放 `/etc/malody-qqbot/appsecret`，属主 root、权限 0600，不放在仓库、环境变量或命令参数中。
用 systemd `LoadCredential` 传给进程，SDK 访问令牌只留内存。

使用 `malody-qqbot.service`，并在部署机增加 drop-in，通过 `BindReadOnlyPaths` 把真实榜单目录挂载到
`/var/lib/malody-qqbot/rankings`、把 `/var/lib/malody-qqbot-catalog` 挂载到 `/var/lib/malody-qqbot/catalog-source`。
配置中 `catalogue` 对应 `/var/lib/malody-qqbot/catalog-source/catalog.json`。
安装 `publish_catalogue.py` 和对应 catalog service/timer，每10秒刷新公开曲目字段及 B30 摘要到专用目录，
防止 QQ 进程接触排行服务的私有恢复状态。先创建 `/var/lib/malody-qqbot-catalog` 并启动一次 catalog service。
绑定目录可跟随源端原子替换新文件，禁止绑定单个 catalogue 文件导致版本停留。
这些部署源路径不得提交到仓库。服务使用 DynamicUser，只有榜单与谱库的只读视图，不授予原始分数或私钥访问权。
发布器用排行服务的私有状态生成 B30 摘要，逐一核对总 rating、分表 rating 和收录数量。
在发布器的 drop-in 中只读挂载 v2 榜单到 `/var/lib/malody-qqbot-rank-source`，并设置
`MALODY_QQ_RANKINGS=/var/lib/malody-qqbot-rank-source`。私有状态保留在原有路径。

图片生成依赖 `fonts-noto-cjk`。机器人只读挂载已发布曲绘到 `/var/lib/malody-qqbot/artwork`。
曲绘依次回退封面、背景和谱面元数据，兼容唯一的大小写文件名匹配；不会拿不相关图片填补缺失曲绘。
如需谱面图片回退，为发布器只读挂载各谱面目录到 `/var/lib/malody-qqbot-chart-source` 下相应子目录，
设置 `MALODY_QQ_CHART_SOURCE=/var/lib/malody-qqbot-chart-source`。生成的缩略图只写专用 `thumbs` 目录。
通过官方 `file_data` 接口上传图片，再被动回复触发消息，不提供公开图片目录或公网下载链接。

在 QQ 开放平台添加测试群到服务范围；如后台要求 IP 白名单，填写服务器出口地址。
使用官方 WebSocket 接入，不开放新的公网 HTTP 端口。首次上线后由管理员在群内 @机器人发送「帮助」「总榜」验证。
SDK 初始化和回复失败日志只记录错误类别，不记录消息、凭据和群成员标识。

`python -B -m unittest discover -s tests -p 'test_qqbot*.py'` 验证查询、排序、去重限流、绑定隔离、B30及曲绘回退。
旧榜单超过两分钟会明确标记延迟，损坏或命名空间不符的数据不会当作有效排行返回。

## 推分推荐

`@小师妹 推分推荐` 根据跨群绑定QQ与发布的B30摘要，返回最多5首可提升综合rating的候选，附ID、键数、等级、分表、判定／准度目标及独立增益。按同歌身份去重、promote优先归N、O20/N10截取及固定除30重算替换结果。没有绑定、没有成绩或摘要不同步时明确提示，不读未上传记录。

各键数独立定推荐上限：取准度≥97%的第三高歌曲等级；不足3首时只推荐已有歌曲，完全没有高准度依据时仅在已玩最低等级巩固。未知键数成绩仍计入基准B30，但不用于猜测键数。低准度越级成绩不抬上限；候选等级不得超过上限，不切换未验证键数。已有成绩沿用原判定、准度最多增加0.3并封顶99.8；新歌参考最近等级最多5首的中位判定／准度，加0.3并封顶99.5。未来表现只是目标，不是能力保证；各条增益独立，不能相加。无安全候选时不自动放宽等级。未评估个人手型及同级内难度差异，回复提醒先读谱、吃力降级。

`@小师妹 等级 14`（或 `/等级 14`、`等级表 14`）按当前折算定级生成14级段完整曲绘图；支持1～15整数查询。按六维已有数值的最高项归为物量、同押、爆发、长按复合、滑键、变速，完全相同按该顺序确定，缺少有效数据单列待分析。每张谱面只展示一次，同歌不同难度仍独立展示，不制造小数定级。曲绘下显示曲名、CID，键数已确认时加角标；沿用查歌的隐藏规则，缺图明确占位。分组是谱面倾向，不代表同等级内部的难度排序。

歌曲名称和歌手优先从 MC 的 `meta.song.titleorg`、`artistorg` 读取，缺失或空白时分别回退 `title`、`artist`，最后回退数据库字段。原数据库名称、文件译名仍保留为搜索关键词。导出器按文件路径、修改时间、大小与谱面hash缓存读取结果，不修改源文件。数据库等级缺失时补读难度名中明确的1～15级正数标记（如“大师9级”）；负数或冲突等级不推断。

`@小师妹 /歌曲别名 歌曲编号 别名` 添加公开查歌别名，编号可用歌曲信息图中的谱面ID（CID），也支持SID；编号冲突时CID优先。同SID各难度共用，跨群共用，重启持久保存至私有状态目录 `song-aliases.sqlite3`，不改写谱面或曲库原始名称。所有玩家可添加；重复别名按Unicode规范化及忽略大小写去重，每首最多40个、每个1～48字。禁止控制字符及@、尖括号；不可查询的隐藏谱面不能添加。

歌曲信息及推荐消息下方的「添加别名」按钮填入编号，玩家补上别名后发送。别名进入查歌搜索字段；信息图与推荐图末尾自动换行展示全部已保存别名。别名不绕过既有谱师隐藏规则。没有SID的谱面以CID独立保存。

`@小师妹 谱面预览 谱面ID` 返回 EX Rhythm Master VI 等宽直轨展开图。也可输入歌名，多难度会列出 ID。机器人只读预先生成的 PNG，不加载原始 MC 或执行皮肤脚本。服务与目录配置见 [谱面预览服务](../chart_preview/README.md)。

图片上传 HTTP 超时为30秒；超时没有返回媒体信息时给出明确提示，避免后续将空返回值当作上传结果。

## 六维算法说明

`六维算法`／`六维规则`／`六维参考` 返回现行公式、参考歌曲和各键数100分基准；“歌曲与谱面”菜单提供按钮。物量以《诸神黄昏》3885音符头＝100；爆发与滑键均按BPM分段换算后的真实连续4秒统计，滑键强度＝全曲总折点数^0.7×全曲实际折点密度^0.2×最密4秒折点密度^0.1，再以《风纪委员》与《GOODRAGE》4K HD综合强度均值＝100。详见 [当前六维规则](../../docs/radar-current-rules.md)。

## 歌曲推荐与两小时定时推送

- `歌曲推荐`（别名 `推荐歌曲`、`随机推荐`）：随机歌曲卡，含曲绘、歌名、BPM、可见难度和各谱面前五名排行榜；优先选取有可用曲绘的歌曲。无成绩或榜单不可用会明确标注。
- `开启推荐`：先立即尝试一张不携带旧 msg_id 的主动推荐；平台确认发送成功后，启动本群每7200秒一次的定时任务。
- `关闭推荐`：停止本群自动推荐，手动查询仍可使用。
- `推荐状态`：查看开启状态、北京时间下一次发送时间及最近结果。

分群设置与最近20首推荐记录保存在私有 STATE_DIRECTORY/recommendations.sqlite3；重启后保留。每30秒检查到期任务，发送前预留下一时段，停机期间不补发、不失败连发。被允许的群才参与定时发送。QQ群需要允许机器人主动推送；主动发送失败不会伪造过期 msg_id，也不会假称已开启。所有人可在当前群开启/关闭，群设置相互独立。日志仅记录成功或错误类型，不打印群ID、消息正文或密钥。

## 按需谱面视频

`@小师妹 谱面视频 歌名或谱面ID`（别名`视频预览`）。多谱面匹配先列出ID，不擅自选择难度。菜单的「谱面视频」按钮填入指令，等待玩家补充歌曲。

首次查询先回复“这是该谱面当前版本的首次生成”，再异步生成完整带原曲视频并发送。缓存命中直接发送，不再渲染。相同谱面并发查询共用一个任务，等待者提示已加入任务。全局一个低优先级渲染进程，最多三个不同谱面任务（含等待），不占用查榜请求槽位。等待超过150秒会告知仍在后台制作、稍后查询缓存；单次渲染限180秒，超时终止整个子进程组，失败不写有效缓存。

缓存位于机器人私有`STATE_DIRECTORY/videos`，重启保留。缓存键包含时间线内容、谱面服务器身份、曲绘内容、歌曲标题与难度、渲染器及全部素材版本；谱面或皮肤变更会生成新键。视频和摘要原子替换，仅完整、大小及SHA256校验通过的视频可复用。只读取已发布playback时间线、去重音乐及公开曲绘，不读取玩家原始成绩、执行MC脚本或Lua。当前支持4/5/6K，完整视频最长10分钟、输出不超过30MiB。

机器人运行环境额外安装`numpy`和`imageio-ffmpeg`。将`tools/render_gameplay_video.py`部署到`/opt/malody-video-renderer/tools/`；保留其`android/assets/gameplay-skin/1712474142416.png`和`rm-notes/`相对目录。在`/opt/malody-video-renderer/tools/revision.txt`写入渲染器源码及所有素材的内容摘要，更新任意文件后重新计算。可用配置`video_renderer`覆盖脚本绝对路径。系统需有NotoSansCJK常规和粗体字体。playback通过现有chart-previews只读挂载访问，不新增源谱面或私有恢复状态挂载。

视频使用QQ官方群聊分片上传：`upload_prepare` → HTTPS PUT分片 → `upload_part_finish` → `/files`合并 → 回复原请求。兼容文档中的0起始与线上实际1起始的连续分片编号，按数组偏移切割文件、按服务端编号确认。PUT不附带机器人鉴权，不新开公网端口，不使用超过5MB的base64直传。QQ上传失败保留本地视频缓存，下次查询重新上传。已使用A Site完整缓存视频核验真实预上传、PUT、分片确认及合并成功；群内最终视频展示仍由测试群确认。

接口参考：[官方群聊预上传](https://bot.q.qq.com/wiki/develop/api-v2/autogen/api/v2_groups_group_id_upload_prepare.post.html)、[分片完成](https://bot.q.qq.com/wiki/develop/api-v2/autogen/api/v2_groups_group_id_upload_part_finish.post.html)、[群聊富媒体上传](https://bot.q.qq.com/wiki/develop/api-v2/autogen/api/v2_groups_group_openid_files.post.html)。
