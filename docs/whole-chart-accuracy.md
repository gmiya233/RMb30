# 整曲准度上限校正（1.6.30）

原始accuracy_candidate和raw_score_fields全部保留，修正结果只用于排名、B30、最近成绩和称号资格；不写回Malody或覆盖云端原始记录。

云端没有逐个COOL的细分权重，也没有可信的皮肤身份。现有RM VI脚本显示COOL可能为90／85／80%，长条会产生额外计数，不同皮肤的计数容量不同。因此此版本实现的是**兼容性保守的整曲准度上限**，不是精确重建全部漏打判定。不能把“实际判定数量”简单除以音符头后当作精确准度。

对支持的静态Slide谱面发布：

- `judgement_rule = slide-whole-accuracy-upper-v1`。
- `judgement_count`为可确认的最小整曲判定容量：可玩音符头数量与静态RM VI容量取小值。真实皮肤容量可能更大，所以这只是宽松上限。
- `rmvi_judgement_count`仅供诊断，按所附皮肤的IMD/MC长条与分段规则静态计算，不执行Lua。
- 绑定CID、server_hash，并保存源摘要。带脚本、无法读取或不支持的模式不猜测容量。

成绩字段7／8／9／10分别对应BEST／COOL／GOOD／MISS；不使用字段6最大连击作为完成量。此映射由皮肤的Play:SetCountByType与现有记录核对。判定权重未知时，每个成功判定最多贡献100%，MISS贡献0：

`上限 = min(100, 100 × (BEST + COOL + GOOD) / 最小整曲容量)`

`榜单准度 = min(原始准度, 上限)`

不因原始分数很低直接删除记录。缺少判定计数、缺少兼容元数据的历史成绩暂保留原准度，不宣称已经核验其完赛；非法计数不用于计算。以后若增加可信皮肤版本、逐判定回放和精确容量，可进一步收紧上限。

Alpharise（CID604391）静态IMD含2496个可玩音符头，RM VI容量5125。目标记录BEST=1、总分2000、原始准度100%，新上限为100/2496≈0.040064%，单曲rating从14降到约0.000002247。源记录不变。已核对的两条完整高准样本保留原准度。

现网20个存档共853条历史记录的只读审计中，2条触发此上限，851条保持原准度。另一条是同CID历史判定数量少于当前谱面的记录，可能涉及旧版本差异；下调不代表作弊结论。所有原始数据继续保留。

索引命名空间升级为`index-v4-whole-accuracy:`，包含容量规则和数量，防止混用旧准度的最佳成绩。服务器从完整历史重新挑选最佳成绩，旧快照保留。Android、服务器共享AccuracyRules；Swift源码同步等价规则，但本次不发布新的IPA。

验证包括一击退出、完整全准、Miss、原始数据不变、非法字段、未知元数据兼容，静态IMD／MC计数和BPM区间，以及排行命名空间的Java/Swift共享测试向量。
