# QQ 群文件批量导入（Android 1.6.4 试用）

玩家使用手机 QQ 自己的登录状态，在群文件多选下载，再回 Malody Link 从已设置的下载目录多选。QQ 当前多选没有「其他应用打开」时不依赖这一入口。App 不读取 QQ 登录凭据，也不请求群文件远程列表。单文件分享和系统多文件选择仍保留。

## QQ群文件下载路径设置

设置 → 群文件批量导入 → QQ群文件下载路径：

- 自动检测：复用已配对的本机读取，按常见目录检测，只列出 MCZ / ZIP，按最新文件时间排序，显示可读取的包数量，由玩家选择保存目录。无线调试关闭、授权失效与目录不存在分别提示。
- 手动选择：调用系统文件夹选择器，仅保留读取授权。下次导入时再次校验权限；授权失效提示重新选择，不把错误显示成空目录。
- 导入页「从已设置目录选择」按最新下载排序列出包名、大小与时间，选择后复制到本 App 缓存检查。没有预设路径时先进入路径设置。
- 受限目录仅使用固定 QQ 下载路径和 ZIP / MCZ 文件扩展名；读前、读后均校验文件大小和修改时间，不扫描 QQ 账号、聊天或数据库目录。
- Android 限制系统选择 Android/data 时，可使用自动检测，或让 QQ 下载到公共 Download/QQ 后手动授权。没有申请所有文件访问权限。

## 操作

1. 在 QQ 中选择已可交接的 `.mcz` / `.zip` 文件，选择 Malody Link。App 接收 `ACTION_VIEW`、`ACTION_SEND` 和 `ACTION_SEND_MULTIPLE`，也处理 ClipData。QQ 实际是否允许多选后调用其他应用，需要在对应版本 QQ 中确认。
2. 确认界面列出包名、大小、谱面数量和前几个曲名；无有效 `.mc`、重复或无读取权限的文件单独显示原因。
3. 勾选后准备导入，默认使用逐包兼容模式，保持原包根目录与文件相对路径；点按钮交给 Malody，返回后继续下一包。
4. 可关闭兼容模式试用整合导入：各源包置于独立子目录，生成一个 MCZ 后交给 Malody。该方式尚未在真机确认，游戏不识别时请使用默认逐包模式。

QQ 如果没有多选后「其他应用打开／分享」选项，可以先下载文件，再从设置中的「群文件批量导入」用系统文件选择器多选。

## 范围与验证

- 每批最多32个包，单包不超过256MB，输入合计和解压后合计各不超过1GB。
- 校验 ZIP 路径、MC JSON 结构和源文件 SHA-256，拒绝跨目录路径、重复包、无效包；失败包不阻塞其他包的检查。
- 只在本 App 缓存中复制和重建导入包；通过只读 ContentProvider 临时授权 Malody。直接打开的目标为 Malody V（`me.mugzone.emiria`）。
- 交接不等于导入成功。游戏未提供结果回执，界面不把返回 App 当作成功。
- 已通过合成谱面包的目录隔离、相对音频保留、原始根目录兼容、重复拒绝、异常中断与源文件变化检查，以及 APK 构建。
- 只读检查连接平板的 Malody 清单，确认其声明了 content URI 与 MCZ/ZIP 打开能力；未向平板 Malody 写入测试谱面。QQ 实际交接与游戏最终导入均仍需复测。

本功能不使用服务器转存谱面，不依赖小师妹官方机器人，也不读取玩家 QQ 的账号、聊天或私有目录。


## 1.6.4 文件卡片与清理

- 下载目录仅检测 `.MCZ`，大小写不敏感，不列出 ZIP、RAR、7z 或未完成的 `.mcz.part`。
- 路径设置完成后返回导入页，自动加载内嵌文件卡片；不再用弹窗承载文件列表。通过图标下拉选择每屏 2×2、3×3、4×4，记住上次密度，切换不清除勾选。
- 先显示名称、大小、时间，只在确认导入时读取并检查已选包。
- 自动检测优先使用 App 已获得的文件夹授权；无线调试关闭时仍显示这些可读目录。其他候选路径分别标记“未检查”，不能当作可读取的空目录保存。
- 清理支持已选或当前目录全部 MCZ；确认页显示目录、数量、大小和部分文件名，明确永久删除。每个文件删除前再次验证来源、名称、大小、时间；仅能删除当前目录列出的 MCZ，不递归删除文件夹。
- 系统文件夹只有读取权限时，需重新手动选择并授予文件管理权限。清理不会自动重试或绕过授权，不会删除 Malody 的谱面、成绩或回放。
- USB 平板检查：无线调试关闭时，自动检测成功列出已授权目录的52个MCZ；保存后自动返回卡片页；横屏三档分别显示4/9/16张卡片，勾选在切换后保留。检查了删除确认提示，未在测试中执行真实删除。

## 1.6.5 下载扫描修复与按目录清理

- QQ 子目录无权限时保留正常枚举到的 MCZ，并在路径检测和文件卡片页提示扫描不完整。跳过 QQ 临时及缩略图目录；不跳过可能包含真实文件的账号子目录，不修改权限。
- 根目录无权限、索引损坏、连接中断与其他 shell 错误仍报错，成绩读取、复制和删除继续严格检查退出状态。
- 「清理MCZ」新增「选择其他目录清理」：使用系统目录授权，仅扫描 MCZ，展示目录、数量、大小和文件名后再确认删除；取消不删除。临时选择不改变原 QQ 下载路径。
- 自动检测已在连接平板上显示373个可读取 MCZ，并对1个受限子目录给出提示。未执行真实删除或向游戏导入。

## 1.6.6 清理进度

- 清理时使用确定进度条，显示已处理/总数、百分比，以及删除成功与失败数量。每个文件处理完成后推进，失败也计入已处理数，结束后展示清理结果。
- 当前目录、已选文件、另选目录三种清理共用进度；旋转屏幕保留进度状态。
- APK 构建及签名检查通过；不为验证进度执行真实删除。

## 1.6.7 外部谱面冷启动交接修复

- 只读核对连接设备的 Malody 6.6.42 接收代码：MainActivity.onNewIntent 将 URI 转交 Unity 的 SetHandleScheme；MainActivity.onCreate 未包含对应转交。
- 首次交接先启动游戏，8秒后通过 VIEW + NEW_TASK + SINGLE_TOP 再发送谱面；慢启动时提供返回后重试，不宣称固定等待保证游戏完成初始化。
- Provider 仅在文件成功打开后记录读取凭据，返回导入页区分“尚未读取”和“已打开文件”。文件被打开不等于游戏导入完成，需用户确认曲库中出现歌曲。
- 返回 App 不再自动跳到下一包，保留当前包用于重试，用户确认曲库已出现歌曲后才能推进。
- 已通过 APK 构建、签名验证与既有谱面包/路径回归。遵守设备只读检查要求，未通过 USB 向游戏导入测试谱面；实际冷启动导入结果待用户验证。

## 1.6.8 一次性导入全部所选

- 默认合成一个 MCZ 一次发送，逐包模式保留为可选兼容方式。各源包使用独立子目录，保留谱面相对音频和曲绘引用，避免同名文件覆盖。
- 全选不再截取前32包，最多5000包，与目录扫描数量上限一致；文件合计、展开后仍各限1GB，包内文件总数最多20000。
- 用户确认：1.6.7 在 Malody 主界面已运行后，从前台重试可成功导入。删除固定8秒后台自动发送，改为先启动游戏并进入主界面，再从 App 一次发送完整批次，避免将启动成功误认为导入成功。
- 主机回归覆盖40个包合成一个MCZ、40张谱面保留、同名音频逐一隔离及超限拒绝。未通过USB向Malody写入测试数据；实际多曲包的游戏导入结果待用户验证。

## 1.6.9 MCB 多歌曲导入修正

- 1.6.8 的多歌曲包错误使用 MCZ 扩展名，真机反馈不同歌曲被归为同一歌曲。批量导入现改为 MCB；逐包兼容模式保留 MCZ。
- MCB 是多歌曲 ZIP 曲包，各歌曲位于独立顶层目录；不是把每个 MCZ 单独改名，也不是把未解包 MCZ 放进外层压缩包。参考曲包作者说明：https://www.taptap.cn/moment/358650226380113500 ；格式参考：https://github.com/ChuanYuanNotBoat/Catch_Chart_Editor/blob/main/docs/ARCHITECTURE_FORMAT_REFERENCE.md 。本机安装的 Malody 元数据包含 .mcb，且系统能将对应 content URI 解析到其接收活动。
- URI、输出后缀及 Provider 文件名全部保持 .mcb。每个原始包使用基于内容 SHA-256 的独立顶层目录，保留原始相对资源路径；避免不同批次复用 pack-1 等目录而覆盖已有歌曲。
- 回归覆盖两首歌曲的两个顶层目录、40首歌曲/音频隔离、单包MCB目录结构、不同批次目录名稳定、多歌曲MCZ拒绝及Provider文件名限制。游戏端实际分歌结果仍待用户确认，未通过USB更改现有Malody数据。
